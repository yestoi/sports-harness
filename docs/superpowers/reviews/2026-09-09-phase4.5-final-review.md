## Critical

### C1. A section that fails at the database level poisons the whole build, writes no row, and records no error

`harness/dashboard/snapshots/__init__.py:116-125` (`section`), `:181-189` (the upsert).

**Claim.** The branch's three stated failure rules — "a failing section marks only itself", "the
row is the report of the failure", "a failed build leaves the previous payload and records the
class name" — all hold for a Python-level exception and all fail for a database-level one, which
is the failure mode the 2 s statement timeout exists to produce.

**Evidence.** `section` catches the exception and writes `{"error": <class name>}` but never rolls
the session back. After a `DBAPIError` the SQLAlchemy Session is deactivated, so every later
statement on it raises. The upsert at `:181` sits *outside* `run_builder`'s `try/except` (that
block ends at `:162`), so it raises too and `run_builder` propagates; `SnapshotScheduler.run_once`
(`harness/dashboard/scheduler.py:171-173`) swallows it and returns `{}`.

The legacy page's `_section`, which this module's own docstring at `:118-120` claims to reproduce
("the `_section` semantics the legacy page already uses ... with the same catch list"), does call
`session.rollback()` — `harness/dashboard/app.py:633`. That one line is what was dropped.

Reproduced against `localhost:5433` with a two-section builder whose first section runs a bad
`select`:

```
snapshot section bad failed: ProgrammingError
snapshot section good failed: InternalError          <- the healthy section fails too
run_builder RAISED: InternalError (psycopg.errors.InFailedSqlTransaction)
    current transaction is aborted, commands ignored until end of transaction block
    [SQL: INSERT INTO dashboard_snapshots ...]
row.error = None | row.payload = {'n': 1, 'cadence_s': 30} | generated_at = <the previous build>
```

No test covers this: both containment tests raise plain Python exceptions
(`tests/test_snapshot_engine.py:75` raises `ZeroDivisionError`, `:208` raises `ValueError`).

**Why it matters on the NAS.** Floor's `_orders` or `_exposure` hitting the 2 s timeout on a game
day blanks `fills`, `exposure`, `vitals` and `venue` as well, leaves `dashboard_snapshots.error`
null, and freezes `generated_at` at the last good build. The operator sees a stale surface with no
error string — the exact opposite of the design's "a surface showing the last good numbers with a
visible age is honest". Pulse's `snapshot_stale` notices only at 2x cadence, and it names staleness,
not a failure.

**Smallest fix.** Two lines, both in `harness/dashboard/snapshots/__init__.py`:

1. Give `section` the session and roll back in the handler, mirroring `app.py:633`. Builders only
   read, so a full `session.rollback()` costs nothing:
   `def section(session, payload, key, fn)` → `except Exception as exc: session.rollback(); ...`.
   (Every call site already has the session in scope: `pulse.py:550-555`, `floor.py:532-538`,
   `study.py:268-271`, `gate.py:137`, `ticket.py:248-250`.)
2. Add `session.rollback()` immediately before `statement = pg_insert(...)` at `:181` so a build
   that poisoned the session by any other route still writes its row.

Add one test that fails a section with real SQL (`select * from no_such_table`) and asserts both
the sibling section and the row.

## Important

### I1. Pulse's `gather` and rule evaluation run outside every guard

`harness/dashboard/snapshots/pulse.py:539-549`.

**Claim.** `gather()` issues fourteen queries and `payload["status"]` is assigned outside any
`section()` call, so one slow query costs the entire Pulse payload, not one panel.

**Evidence.** `build_pulse` calls `gather` at `:541` and assigns `status` at `:546`; only `tape`,
`vitals`, `storage`, `invariants`, `operator_events` and `snapshots` are wrapped (`:550-555`).
`gather` includes a 24 h `distinct on` over `metric_samples` (`:137-142`), a 24 h `job_runs` scan
(`:174-178`), a 30-row `runs.notes` walk (`:179-181`) and `stopped_variants`. Pulse's status word
is polled by the shell on *every* surface at 30 s, so its loss is the most visible failure the
snapshot layer can have. With C1 unfixed, any of these timing out also means no row is written.

**Smallest fix.** Wrap each query group in `gather` so a failed one yields `None` and its rules
fall through to `_absent`, which the rule set already handles (`:98-99`, and the module docstring's
"an absent input is `not evaluated`, never `fine`"). Alternatively guard `gather` itself and, on
failure, emit a status of all-`not_evaluated` rules rather than dropping the payload.

### I2. `sentences_gaps` is specified but no builder writes it, and the schema tests forbid it

`harness/dashboard/sentences.py:97-99, 141-149`; the payload-key tests.

**Claim.** Addendum §3 and ruling B-(e) item 9 say a reason code outside `REASON_PHRASES` "renders
as itself (sanitized) and the builder writes `sentences_gaps: [code]` into the payload, so the next
plan sees it". Nothing writes it, and nothing can without failing a test.

**Evidence.** `grep -rn sentences_gaps harness/ tests/` returns exactly one hit — the comment at
`sentences.py:99` describing the behaviour. `reason_phrase` (`:141-149`) sanitizes the unknown code
and returns it, but drops the fact that it was unknown on the floor. `FLOOR_KEYS`
(`floor.py:102-103`) and `STUDY_KEYS` (`study.py:41-44`) do not list the key, and the tests assert
exact set equality (`tests/test_snap_floor.py:45`, `tests/test_snap_study.py:197`), so adding it
later is a test change too. The signal this exists to raise — the executor emitting a reason code
the vocabulary has never seen — is silently lost.

**Smallest fix.** Have `reason_phrase` return `(phrase, known)` or expose a
`missing_reason_codes(codes)` helper; collect it in `floor._funnel` and `study._declined_rows`,
write `payload["sentences_gaps"]`, and add the key to `FLOOR_KEYS` and `STUDY_KEYS`.

### I3. Pulse restates five cadence numbers that four builder modules already own

`harness/dashboard/snapshots/pulse.py:64`.

**Claim.** `JUDGED_CADENCES = {"pulse": 30, "floor": 60, "gate": 60, "ticket": 60, "study": 600}`
is five literals, and they colour `rule_snapshot_stale` — which is the rule that turns Pulse
BROKEN. Global constraint 14 says every threshold that colours anything is imported from the code
that enforces it.

**Evidence.** Each value already has exactly one home: `pulse.CADENCE_S = 30` (`:41`),
`floor.CADENCE_OUT_S = 60` (`floor.py:70`), `gate.CADENCE_S = 60` (`gate.py:35`),
`ticket.CADENCE_OUT_S = 60` (`ticket.py:33`), `study.CADENCE_S = 600` (`study.py:37`). The values
agree today, so nothing is wrong on this branch; the drift is silent and its symptom is a false
BROKEN on the wall. The module's comment at `:60-63` argues the *concept* differs (judged versus
run cadence), which is true and is not the same as needing the numbers written twice — the
concept difference is exactly "judged is the out-of-window cadence", which is a choice of *which*
constant to import, not a licence to retype it.

**Smallest fix.** Import the four constants and build the dict from them, keeping the name and the
comment: `{"pulse": CADENCE_S, "floor": floor.CADENCE_OUT_S, "gate": gate.CADENCE_S,
"ticket": ticket.CADENCE_OUT_S, "study": study.CADENCE_S}`. No import cycle: none of the four
imports `pulse`.

### I4. The Ticket builder rebuilds `ScoreState` by hand and drops half the null guard

`harness/dashboard/snapshots/ticket.py:144-149`.

**Claim.** The guard tests `home_score is not None` and then calls `int(score.away_score)`, which
raises `TypeError` on a row with a home score and no away score. `game_score_events.home_score` and
`away_score` are independently nullable (`harness/db/models.py:795-796`).

**Evidence.** T14 shipped the helper that gets this right —
`harness/parlay/needs.py:46-53 score_state()` checks both columns — and T15's builder does not use
it, inlining its own construction instead. The result is `payload["cards"] = {"error": "TypeError"}`
for the whole surface, on a shape ESPN can produce. This is a cross-task integration miss, not a
per-task nitpick: the correct helper exists two modules away and is exported.

**Smallest fix.** Call `harness.parlay.needs.score_state` (adapting it to take the leg's team ids),
or add `and score.away_score is not None` to the condition at `:145`.

## Critical

### C1. A whole-build failure is invisible on every surface but Pulse's own ages table

`harness/dashboard/snapshots/__init__.py:171-175` — on an exception outside a section, `run_builder`
writes `generated_at = now` and `error = type(exc).__name__` while deliberately leaving the previous
`payload` in place. `harness/dashboard/app.py:779-782` returns that `error` in the envelope, and
`/api/snap` returns it per row (`app.py:751-753`).

`harness/dashboard/static/js/app.mjs:303-335` — `poll()` reads `body.cadence_s`, `body.payload` and
`body.generated_at`. It never reads `body.error`. `pollIndex()` (`app.mjs:249-267`) never reads
`row.error` either, and `index.html` has no element for one.

Consequence: a builder that has been crash-looping for hours serves a fresh `age_s` (because
`generated_at` advanced) with a stale payload, and the shell renders it as current. The staleness
banner (`app.mjs:168-177`) cannot fire, because the age is genuinely near zero. The ETag changes on
every failed build, so `poll()` even re-renders the same stale payload as if it were new
(`app.mjs:327-333`). The only place the class name appears is Pulse's own ages table
(`pulse.mjs:179-191`), which is itself unavailable when it is Pulse that is failing.

This is the exact failure the runbook tells the operator to look for
(`docs/runbooks/dashboard.md:119-122`, "the payload shown beside it is the **last good build**") and
the exact reading the design says the surface must give. Right now `/api/snap` is the only place it
is visible, and no surface says it.

Smallest fix: in `poll()`, after `markBuild(body.payload)`, if `body.error` is truthy, set the
`shell-stale` banner (it already exists and is a `role="status"` region) to name the surface, the
class name and the payload's own `payload.now`, with the `broken` class. One branch, no new node.

### C2. Floor's venue tripwire reads green when the section failed

```js
const data = venue(payload) || {};
const ok = data.tripwire_ok !== false;
```

`data` is `{}`, `data.tripwire_ok` is `undefined`, and `ok` is `true`. The card then renders the

Smallest fix: `const ok = data.tripwire_ok === true;` plus a `sectionFailed` branch rendering
"unavailable", as `pulse.mjs:131-138` already does for the invariant wall.

### I4. verify.md walker item 18 asks for something the DOM does not render

Item 18: "the snapshot age is under twice the cadence shown beside it."

`app.mjs:163-167` puts `snapshots <age>` in `textContent` and the cadence only in the element's

as written. The staleness *flag* is on screen (the `watch`/`broken` class and the `shell-stale`

Smallest fix: reword item 18 to "the age carries no `watch` or `broken` styling and no staleness

### I5. The documented scheduler off-switch does not take effect as written

`docs/runbooks/dashboard.md:90-92`: "Set `SNAPSHOTS_ENABLED=0` in `deploy/nas.env` and restart
`app-serve`."

correct (`harness/config/settings.py:90`, `SettingsConfigDict(env_file=".env")` with no prefix, so
`SNAPSHOTS_ENABLED` maps to `snapshots_enabled`).

Smallest fix: name the NAS-side file — "edit `SNAPSHOTS_ENABLED=0` into
`/volume1/docker/sports-harness/.env` and `docker compose restart app-serve`; put it in
`deploy/nas.env` too so the next deploy keeps it."

## Minor

### M1. Polling never pauses on a hidden tab

There is no `visibilitychange`, `document.hidden` or `visibilityState` anywhere under
`harness/dashboard/static/js`. A phone left open on Floor keeps polling every 15 s indefinitely.
The addendum sets no rule here and every unchanged poll is a 304 (`api.mjs:19`), and browsers
throttle background timers anyway, so this is a note rather than a conformance failure. A
`document.hidden` check at the top of `loop()` would cost two lines.

### M2. The DOM-rule grep pins four literals and nothing else

`tests/test_dashboard_static.py:43-67` greps `innerHTML`, `outerHTML`, `insertAdjacentHTML` and
`document.write` as plain substrings over each file's whole text. That is the right shape — it
catches a comment-only mention (the safe direction) and no multi-line evasion is possible for those
tokens in valid JS — and it satisfies the global constraint literally. It does not pin `eval`,
`new Function`, `srcdoc`, `setAttribute("on…", …)` or a computed `node["inner" + "HTML"]`. I grepped
for all of these across `static/js`: none occur, and `el()`/`svg()` (`components.mjs:14-36`) only
ever take attribute *names* from object literals in our own source, never from payload data. Adding
the four tokens to `FORBIDDEN_DOM` is one line.

### M3. Study's t4 heat cells show a value with no cluster count

`study.mjs:188-201` renders `cell.text` inside a coloured badge. Every other Study cell goes through
`intervalMark` (`components.mjs:115-128`), which appends `n=N games`. `n_clusters` is present on the
cell (`study.py:143`). Spec §2.3's never-shown line is "a mean without its interval and cluster
count", and the heatmap is the one place that line is not visibly honoured. The `greyed` flag *is*
honoured (`study.mjs:195`), so nothing unreadable is coloured. Smallest fix: append an
`svg("title")`-equivalent — a `title` attribute or a small `n=` suffix — to `heatCell`.

### M4. Pulse's ages table and the header disagree about Floor's cadence

`pulse.py:64` fixes `JUDGED_CADENCES = {"pulse": 30, "floor": 60, "gate": 60, "ticket": 60,
"study": 600}` and `_snapshots` (`pulse.py:529`) stamps that constant onto every row. The shell's
header instead reads the real per-run cadence out of the payload (`app.py:751`, `run_builder`
writing `payload["cadence_s"] = cadence_s`). Inside a game window Floor runs at 15 s, so Pulse's
ages table shows `60 s` in its cadence column while the header measures against `15`. The rule
itself errs lenient, not noisy, so this is a display inconsistency rather than a false alarm.

### M5. Keys written and never read

Not defects on their own, but they are payload weight and, in two cases, a signal the client should
be using: `storage.measured` (`pulse.py:497` — see I2), `build.agree` (`pulse.py:559`),
`equity.grey_below` (`study.py:190`), `payload.badge` (`ticket.py:247`, whose text is restated as a
literal at `app.mjs:17`), `venue.window_h` (`floor.py:521`), `orders[].fair_staleness_s`
(`floor.py:420`), `fills[].fee` (`floor.py:440`).

### M6. `how.mjs` has no `.catch`

`how.mjs:43` chains `.then` off `Promise.all([loadHow(), loadGlossary()])` with no rejection
handler, and `app.mjs:379-385`'s `try/catch` only catches synchronous throws. It is safe today
purely because `loadHow` and `loadGlossary` swallow their own failures (`api.mjs:73-83`, `55-65`).
One `.catch(() => noModule(root, "How it works"))` makes that independent of api.mjs.
