- Item 4: the legacy Funnel's "Signals per active variant" table lists 7 non-replay variants (constrained, nfl_only, no_velocity, sharp_direct, sharp_plus_derived, sharp_two_sided, wide_band) plus a `sharp_two_sided#e82fcd0a1e99` replay row with 0/0, not the six variants the checklist text anticipates; rendering itself is correct.
- Item 6: every row of the legacy "Last 100 signals (primary variant)" table shows `fair = None` while `reason = has_fair`, which reads as internally inconsistent (a rejection reason claiming a fair value exists where none is displayed); worth engineering follow-up though it does not block rendering.
- Item 14: "DAYS TO CEILING" reads "31 partial" — only 1 day above the 30-day floor, and the "partial" qualifier suggests the growth-rate estimate itself is based on incomplete data; this is a thin margin worth monitoring even though it is technically a PASS today.

- Item 26: tab-bar and glossary `<button>` elements report `type: "submit"` in the DOM (the HTML default when no `type` attribute is set), even though no `<form>` element wraps them anywhere on the sampled /ui/ pages; functionally inert but worth a small code-hygiene fix (`type="button"`) to remove ambiguity.
