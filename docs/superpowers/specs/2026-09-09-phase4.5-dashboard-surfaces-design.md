# Phase 4.5: Dashboard Surfaces (Pulse, Floor, Study, Gate, Ticket). Design Addendum

Date: 2026-09-09, revision 2 (revision 1 reviewed by two opus design reviewers; every finding is ruled on in the Rulings section at the end and applied here). Written by the autopilot under the roadmap's standing authorization of 2026-09-07 ("Brainstorm, plan, and execute phases 4, 5, 6 without waiting"; `docs/superpowers/autopilot/roadmap.md`, Standing authorizations; the phase table lists 4.5 as "plan-next from the spec and its design canvas"). The roadmap's "Pre-loaded decisions, Phase 4.5" items 1-7 and decision U6 are the user's answers; every other choice is under §11 with its cost and reversal. The dashboard spec (`docs/superpowers/specs/2026-09-07-dashboard-surfaces-design.md`, "the spec" below) is the brief: its §2 surfaces, §3.8-3.9 tables, §4 snapshot layer, §5 front end, §6 budgets and §8 tests are binding and are not restated here; this addendum fixes what the spec left to the plan, amends it where the code on `main` (4c554ea) says it must, and folds in the carried items the phase 4 report and journals 77-82 assigned to phase 4.5. Where this addendum and the spec differ, this addendum wins for phase 4.5.

**Posture.** Read-only. Nothing in this phase writes to a venue, moves money, or changes a strategy, a variant, a threshold or a gate criterion. The only writes the dashboard keeps are the frozen `/kill` and `/unkill` pair. The Ticket surface shows real fun money from tables that stay empty until phase 5c; no code in this phase writes those tables except the schema itself.

## 0. Amendments to the spec (and the phase 4 addendum where named)

1. **Snapshot cadence is scheduler-driven for every name, including closed Study weeks (spec §4 "once on demand").** No request handler ever reaches Postgres: `GET /api/snap/{name}` reads `dashboard_snapshots` by primary key and nothing else. A closed week's `study:<year>-<week>` snapshot is built by the scheduler's `study` job, which every 10 minutes lists the `(year, week)` pairs present in `report_runs` and rebuilds any whose newest `report_runs.id` differs from the `report_run_id` recorded inside the snapshot payload. A week with no run has no snapshot and the surface says so. Spec §0.3 ("no page view runs a query") therefore holds without exception.
2. **The builders' forbidden-table list grows from three to five.** Spec §4 forbids `orderbook_events`, `venue_trades` and `raw_responses`. Phase 4.5 adds `odds_snapshots` and `venue_quotes`, the two tables behind the legacy page's remaining unindexed reads (state.md deferred item; fix 25's `_unmatched_markets` and `_data_quality` staleness). This is exactly the set `deploy/backup/dump.sh` excludes from the nightly dump, so "forbidden to builders" and "excluded from the dump" are one list. Everything a surface needs from them already exists in `metric_samples` (`pricing.staleness_median_s{feed_kind}`, `match.unmatched{sport}`, `match.rate{sport}`) or in `runs.notes`. A static test asserts no builder SQL names any of the five. The legacy page keeps its own bounded reads, frozen. Two spec §2.1 rules are re-sourced for the same reason: the `gap` rule reads `sum(ws.gaps)` over 2 h from `metric_samples` (the WS recorder writes it per minute), never `orderbook_events`; the Floor funnel's tick, gap and signal counts come from `runs.notes` exactly as the legacy funnel does since fix 15 (a direct 6 h scan of `market_gap_snapshots` and `signals` took 86-92 s; their indexes lead on market and variant, not time), and only `intents`, `order_events`, `orders` and `fills` are read directly, each bounded by its existing time-leading index.
3. **Phase 4 addendum §0.3 (drawdown alert) lands as a Pulse rule, and phase 4 item 7 (`venue_requests`) as a Floor tile** (roadmap phase 4.5 item 5). Pulse `WATCH` (rule `drawdown_stop`) when `harness.execution.risk.stopped_variants(session, now)` is non-empty; the value shown is the variant's newest `drawdown_pct` and the threshold is `harness.execution.risk.DRAWDOWN_STOP_PCT`, imported, never restated; never `BROKEN` in paper, per the phase 4 amendment. Floor's **venue tile**: `venue_requests` rows in the last 24 h by `env` and `method`, the production non-GET count with its tripwire (0, red on anything else), the newest `venue_status` row per env, and the last demo smoke's result from the newest `operator_events` row of kind `note` whose summary starts with `demo smoke` (the verify pass writes it with `harness note --kind verify_pass`), else "no smoke recorded".
4. **Three `check_results` definitions are corrected (journal 79; a third failing check, `metric_samples_negative_24h`, cleared on its own at 10:02 CT when the pre-clamp rows aged out: 0 negative rows in 24 h and 0 since the phase 4 clamp, measured 11:10 CT, so it needs no change).** (a) `intents_without_order_or_skip` considers intents created in the last 24 h (bounded like its siblings) and also accepts an intent whose `(variant_id, venue_market_id, side)` key had an order **working at the intent's `created_at`**: `placed_at <= i.created_at` and either `status in ('open', 'partially_filled')` or a `cancel`/`expire` event with `ts >= i.created_at`; the executor's hold path writes no event by design (2,459 such rows on 2026-09-09, every one with a working order on its key, 2,452 then superseded by the next pricing run's intent). An additive index `ix_orders_key_placed (variant_id, venue_market_id, side, placed_at)` on `orders`, built `CONCURRENTLY` through the same autocommit helper as `ix_fair_created_brin`, keeps the correlated lookup inside the checks' 2000 ms timeout; the plan task tests the boundary (an order cancelled before the intent's creation does not excuse it). (b) `build_sha_drift` compares against the newest `runs.build_sha` only for runs started after that build's first appearance, so a deploy day no longer fails it for 24 h while a container whose rows continue with the old sha after the new one appears still fails it. `runs` is written by the recorder alone, so this check covers `app-run` only; Pulse's build tile shows `runs.build_sha`, `exec_heartbeat.executor_version` and the serving build sha side by side so executor and dashboard drift are visible even though the check cannot see them. (c) `fair_values_negative_feed_lag`, the one unbounded statement left in the registry (it has been `skip` on timeout every day), is bounded by `created_at > now() - interval '24 hours'` through the existing `ix_fair_created_brin`, as fix 16 did for its sibling. All three remain named, bounded, tape-free checks; the verify.md row still says "all pass". The Pulse invariant wall would otherwise be red on every day with a deploy or a held intent, and grey over a check that never runs, which are the failures the wall exists to avoid.
5. **Fonts (spec §5 "no font download"; canvas README names Space Grotesk for display, IBM Plex Sans for text, IBM Plex Mono for numerals).** No font file is vendored in this phase: the stylesheet prefers `"Space Grotesk"` for display, `"IBM Plex Sans"` for text and `"IBM Plex Mono"` for numerals, each falling back to the system stack (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`; `ui-monospace, "SF Mono", Menlo, Consolas, monospace`). The canvas's proportions are kept with the fallback metrics. The artboards' `fonts.googleapis.com` stylesheet link must not survive the port (the no-external-URL test). See §11 D5 for the reversal.
6. **Table t12 is appended to `TABLE_KEYS` after `t10`** (spec §3.7), so `harness report` renders and persists it last and the `report_wtd` stage carries it. Its first column is the composite `variant/reason` string (so `Table.row_key`, which is the first column, is the row's identity rather than a positional `#N` suffix; `t11` has the same positional defect today and is noted, not fixed here), and its counterfactual CLV columns name their estimator in the column key (`clv_rejected_gap_outcomes`, `clv_skipped_intent_snapshot`) because rejected signals and skipped intents use different estimators. It is "reported, never gated": the gate reads `gate_reports` only (R1 untouched; the criteria, families and thresholds are not edited). The markdown gains one additive table. `report_wtd` runs **six-hourly** on `main` (`report_wtd_period_s`, final review I6), not hourly as the spec's §3.7 says: a Study snapshot rebuilt every 10 minutes can therefore carry provisional cells up to six hours old and shows the cell age beside the `provisional` label; t12 is an eleventh table in a stage that already yields below `MIN_BUDGET_S`, and the cadence setting is not changed in this phase.
7. **The restore drill compares against dump-time counts (phase 4 report §7).** `deploy/backup/dump.sh` writes `tables.counts` (exact `count(*)` per dumped table, the five excluded tables omitted) into `.meta.json`; `drill.sh` compares the restored counts against those and reports `ROWS_MATCH true|false` from that comparison, never from the live database. Runs in the same 03:30 CT window; the counts cost one scan of `signals` (the largest dumped table) per night.
8. **Smoke detail carries the confirming-read attempts** (journal 80 ruling (d)): the `place` and `amend` step details gain `reads=N` (the number of confirming reads the echo check made, 1-4), so lag drift toward the 1.5 s ceiling is visible in the step table before it becomes a freeze. `VenueOrder` gains `confirm_reads: int`; no behaviour change in the adapter.
9. **Threshold homes (spec §1.1 "imported from the code that enforces them").** The executor's 60 s and 120 s do not exist in `harness.execution`; they are literals in the legacy dashboard (`HEARTBEAT_RED_S = 60`, `WS_EVENT_RED_S = 120` in `app.py`). This phase gives every Pulse threshold one home in `harness/health.py` beside `STALE_AFTER_S` and `CREDITS_LOW_FRACTION`: `HEARTBEAT_WATCH_S = 60`, `HEARTBEAT_BROKEN_S = 120`, `WS_EVENT_WATCH_S = 60`, `WS_EVENT_BROKEN_S = 120`, `CREDITS_WATCH_FRACTION = 0.4`, `DISK_FREE_MIN_FRACTION = 0.25`, `DB_WATCH_FRACTION = 0.6`, `DB_BROKEN_FRACTION = 0.8`; the legacy page imports `HEARTBEAT_WATCH_S` and `WS_EVENT_BROKEN_S` in place of its two literals (same values, no behaviour change). Housekeeping additionally records `host.disk_total_gb` beside `host.disk_free_gb` (one additive metric name from the same `statvfs`), so the 25 % rule is computable; until the first housekeeping run after the deploy the disk rule reports "not evaluated", never a false `FINE`.
10. **`readings` (spec §4) are kept**, not dropped: Gate criteria rows, Study declined rows and Pulse fired rules each carry a per-row plain sentence under `readings`, produced by `harness/dashboard/sentences.py` beside `sentences`.

## 1. Snapshot layer (`harness/dashboard/snapshots/`)

- **Engine.** `make_snapshot_engine(settings)` builds a second engine from `settings.database_url` with `connect_args={"options": "-c statement_timeout=2000"}` (`SNAPSHOT_STATEMENT_TIMEOUT_MS = 2000` in `harness/dashboard/snapshots/__init__.py`, asserted below the sink's timeout by a test), `pool_size=2, max_overflow=0`. The request path keeps the existing engine and never calls a builder.
- **Scheduler.** `SnapshotScheduler` (`harness/dashboard/scheduler.py`) wraps APScheduler's `BackgroundScheduler` (already pinned, `apscheduler==3.11.3`) with a two-thread executor, started and stopped in the FastAPI `lifespan` only when `Settings.snapshots_enabled` is true (default true; the test fixtures set it false and drive `run_builder` directly); one job per name, `max_instances=1`, `coalesce=True`, `misfire_grace_time` equal to the cadence. Cadences: `pulse` 30 s; `floor` 15 s inside a game window, 60 s outside, decided by `harness/dashboard/window.py::game_window_open(session, now)` (the R4 rule as one bounded query over `games`: any matched game `in_progress`, a kickoff in the last 4 h or the next 15 min, or an NFL kickoff 60-100 min away), re-evaluated on each run and the job rescheduled when it flips; `study` 10 min (current week plus catch-up per §0.1); `gate` 60 s; `ticket` 15 s in a game window while any card is `placed` or `alive`, else 60 s. **CPU budget (spec §6, 2 s per minute):** every build records `serve.snapshot_ms{name}` through `harness.telemetry.record` on the builder's own session; when `floor`'s p95 `elapsed_ms` over the last 10 minutes exceeds 250 ms the in-window floor cadence backs off to 30 s and a `WATCH` rule `snapshot_budget` names it; the verify row checks the per-minute sum.
- **Builder contract.** `Builder = Callable[[Session, datetime, Settings], dict]`. `run_builder(name, builder)` opens a session on the snapshot engine, calls the builder inside `_section`-style guards (one failing section marks that section `{"error": <class name>}` and the others survive), and upserts `dashboard_snapshots(name, generated_at, elapsed_ms, payload, error)`; an exception outside a section writes `error` as the exception **class name** (80 chars, never `str(exc)`, whose text may carry SQL or row content) and leaves the previous `payload` untouched. Every payload carries `build_sha`, `now`, `cadence_s`, `sentences`, `readings` (§3) and, for Study, `report_run_id`.
- **Sanitizer (provenance rule).** Every string of outside provenance passes `harness.telemetry.sanitize_reason` (the F50 sanitizer `/kill` uses) before it enters a payload; there is no exemption list. Outside provenance means: venue tickers and market titles, `venue_status.reason`, match reasons, ESPN team names (`teams.display_name`, `name`, `abbreviation`, `short_display_name` are copied verbatim from ESPN's `/teams` body), ESPN scoreboard text (`game_score_events.status`, `period`, `clock`), `operator_events.summary` (already sanitized at write; sanitized again, harmlessly), `parlay_legs.plain_text` and `parlay_cards.rationale`, unknown reason codes (`sentences_gaps`). The sanitizer is applied for provenance, not as an output escaper: it is **not** applied to `report_cells.text` (shown as stored, spec §1.1) or `report_runs.markdown` (§4's DOM rule protects the page). `runs.notes` is never passed through as an object: the funnel takes named integer counts out of it. A test feeds a hostile fixture through each builder and asserts every enumerated provenance field contains no control characters and no markup.
- **API.** `GET /api/snap` lists `{name, generated_at, age_s, cadence_s, elapsed_ms, error}` for every row; `GET /api/snap/{name}` returns `{name, generated_at, elapsed_ms, cadence_s, payload}` with `ETag: "<name>:<generated_at isoformat>"` and answers `304` to a matching `If-None-Match`; unknown name `404`; `Cache-Control: no-cache`. Names are validated against the builder registry plus the anchored pattern `^study:\d{4}-\d{1,2}$`; nothing else reaches the table lookup or a header. The payloads disclose more than `/api/summary` does (gate criteria, per-variant equity and cash, open positions, queue positions); the loopback binding and the ssh tunnel are the stated control (spec §9), recorded in the runbook.
- **Static.** `app.mount("/ui", StaticFiles(directory=<package static dir>, html=True), name="ui")` with the directory resolved through `importlib.resources` exactly as `_templates_dir` resolves templates, wrapped so every static response carries `Cache-Control: no-cache` (revalidation only, so a phone never renders a cached shell against a new payload shape; the shell also shows the payload's `build_sha` beside its own and flags a mismatch); `pyproject.toml` package-data gains `dashboard/static/*`, `dashboard/static/js/*`, `dashboard/static/vendor/*` (an explicit list, not a recursive glob). Root `/`, `/api/summary`, `/healthz`, `/kill`, `/unkill` are unchanged and covered by the existing tests plus a new one asserting `/api/summary`'s nine checked keys and section names are those of `main` (a frozen fixture).

## 2. Builders (one module each under `harness/dashboard/snapshots/`)

Each builder implements exactly the spec's §2 metric table for its surface and nothing more; the "never shown" lists are enforced by a payload-schema test per builder (the schema names the allowed top-level keys and a Pulse payload with a `pnl` key fails the test). The shared read helpers the legacy page already has (`_recent_run_notes`, `_signals_by_variant_from_notes`, `_local_day_bounds_utc`) move to `harness/dashboard/queries.py`, the legacy page importing them from there with no behaviour change.

- **`pulse.py`.** Status word and the fired-rule list per spec §2.1, each rule a named pure function over the gathered values with its threshold imported from §0.9's homes (`harness.health`), `settings.db_budget_gb`, and `harness.execution.risk.DRAWDOWN_STOP_PCT`; plus `drawdown_stop` (§0.3), `check_skipped` (`WATCH` on any `skip` in the latest sweep) and `snapshot_budget` (§1). Rules whose input is absent (no housekeeping run yet, no heartbeat row) report `not evaluated` and never contribute `FINE`. Tape strip and sparklines from `metric_samples` (bounded: `name in (...) and ts > now - 24 h`, index `(name, ts desc)`), vitals from `exec_heartbeat` and the newest `runs` row via `compute_health`, storage from `job_runs.notes` (housekeeping) and `metric_samples` `db.*` and `host.disk_*`, the invariant wall from the newest `check_results` sweep (`ts = max(ts)`) with three tile states (`pass`, `fail`, `skip` with the `detail` string), operator events `order by ts desc limit 10`, snapshot ages from `dashboard_snapshots`, the build tile of §0.4(b).
- **`floor.py`.** Game board from `games`/`teams`/`venue_markets` (kickoff within 24 h or `in_progress`), live score from `game_score_events` newest per game (labelled with age), open orders with `order_watch_samples` sparklines (`order_id in (open ids)`, last 2 h), fair and edge for open orders from `fair_values` newest per market bounded by those market ids through `ix_fair_game_type_created`, fills `limit 50` today (CT day bounds via `_local_day_bounds_utc`), the funnel over 6 h per §0.2 (`runs.notes` sums for ticks, gaps, candidates and rejections by variant; direct bounded reads of `intents`, `order_events`, `orders`, `fills` for intents, skips by reason, orders, cancels by reason and fills), exposure lanes from `positions`, `orders`, `fills` and the newest `equity_snapshots` per variant, vitals from `metric_samples` (2 h), and the venue tile of §0.3.
- **`study.py`.** For a `(year, week)`: the newest non-provisional `report_runs` row (or the newest provisional one for the current ISO week, labelled `provisional` with its `generated_at` age), every `report_cells` row of that run keyed `table_key -> row_key -> col_key` with `text`, `estimate`, `n_obs`, `n_clusters`, `lo`, `hi`, `flags` verbatim; equity curves from `equity_snapshots` over the week per variant as two series (cash; cash + `mtm_open`) with `mtm_coverage` carried per point, the MTM line drawn grey below 0.5 coverage and `study_equity`'s sentence stating the coverage; annotations from `operator_events` in the week; `markdown` and `markdown_sha256` from the run row. The UI computes nothing: the forest plot, heatmap and ledger are drawn from cells. Week list from `report_runs` (ISO weeks from 37).
- **`gate.py`.** The newest `gate_reports` evaluation: one row per variant with `criteria_json`, `criteria_hash`, `passed`, `gate_variant`, `evaluated_at`, variant names from `strategy_variants`; the history of each criterion across every stored evaluation (`order by evaluated_at desc limit 200`); `readings` per criterion row.
- **`ticket.py`.** Cards, legs, placements, ledger, leg probabilities from the §3.9 tables (`limit` by week), the season strip, and the between-cards state (next build day from the calendar, the anchor rule, the week's budget left = 50 - staked this ISO week). `needs(leg, score)` from `harness/parlay/needs.py`. With the tables empty (this phase), the builder returns the between-cards payload and `sentences` for it.

## 3. Sentences, readings, glossary, reason phrases (`harness/dashboard/sentences.py`, `static/glossary.json`)

- One pure template function per surface section (`pulse_status`, `pulse_tape`, `floor_board`, `floor_funnel`, `floor_orders`, `study_ledger`, `study_contrasts`, `study_equity`, `study_declined`, `gate_verdict`, `gate_criterion`, `ticket_card`, `ticket_between`), each `(payload_section) -> list[str]`, sharing `confidence_phrase(n_clusters)` (three bands per spec §1.2: below 10, 10-29, 30+) and `reason_phrase(code)`; `readings` producers `gate_criterion_reading(row)`, `study_declined_reading(row)`, `pulse_rule_reading(rule)` return one sentence per row. A greyed cell yields a sentence that states no estimate. Numbers in sentences are formatted by the same helpers the evidence uses (`fmt_prob`, `fmt_money`, `fmt_int`), so no rounding drift; `study_declined` names the estimator of §0.6.
- `REASON_PHRASES` is the spec §1.2 vocabulary table as a dict keyed by code; a test imports every skip, cancel and rejection code the executor and strategy can emit (`harness.execution.plan` reason constants, the strategy's `rejection_reason` set, the `order_events.reason` values in `tests/fixtures`) and asserts each has a phrase; a code outside the table renders as itself (sanitized) and the builder writes `sentences_gaps: [code]` into the payload.
- `glossary.json`: one entry per vocabulary row (`term`, `plain`, `what`, `why`) plus every technical name a surface renders in small type; a test walks the `LABELS` constants the surface modules declare and asserts each technical name has an entry.
- The How-it-works content (eight pipeline steps, the three jobs, what paper means, the honesty rules, the full glossary) lives in `static/how.html` as fixed text rendered by the client from `glossary.json` plus that text, reviewed against spec §1.2.

- **Accessibility.** Tabs as `role="tablist"` with `aria-selected` and arrow-key movement; the glossary term is a `<button>` that opens on tap, click or keyboard focus (hover is a bonus, never the only path); the Pulse status word sits in an `aria-live="polite"` region; every hand-drawn SVG carries `role="img"` and a `<title>` repeating its sentence; tap targets on the phone tab bar at least 44 px; colour never the only signal (every series named beside its mark, per spec §5).

SVG is hand-drawn for funnel, forest plot, heatmap, queue bars, tape strip, storage arc; uPlot only for time series.
- Asset budget test: the sum of bytes under `static/` (vendor included) under 300 KB. No external URL in any static file (a test greps `https?://` and allows only the uPlot LICENSE header and the canvas link in `how.html`; the artboards' Google Fonts link must not survive the port).
- Responsive at 360-2560 px; phone tabs at the bottom under 720 px. Verified by the Chrome walker at 390 px and 1440 px (§9).
