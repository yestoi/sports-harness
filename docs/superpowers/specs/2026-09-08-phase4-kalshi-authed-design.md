## 0. Amendments to the v2 spec and the phase 3 addendum

1. **Expiry (§9.2) stays R8.** No per-cycle renewal; `expiry = kickoff - 10 min` set once; the watcher's cancel-all at kickoff - 10 min is the fast path; the live adapter never exposes `amend(expiry=...)`. Kalshi's V2 amend carries no expiration field, which matches.
2. **Order shape (§5.2).** V2 event-order endpoints replace the legacy `/portfolio/orders`: `POST /portfolio/events/orders`, `POST /portfolio/events/orders/{id}/amend`, `DELETE /portfolio/events/orders/{id}`. `side` in {bid, ask} on the YES leg (buy NO = `ask` at `1 - p`); `price` and `count` fixed-point strings ("0.5600", "10.00"); `time_in_force = good_till_canceled` with `expiration_time` as int64 Unix seconds; reads decode `outcome_side`/`book_side` and tolerate an absent legacy `side`/`action`; the echo check compares `remaining_count` and `fill_count` as Decimals.
3. **Drawdown stop (§9.3) in paper mode** raises a dashboard alert and labels the variant's later signals `drawdown_stop`; it never trips the kill switch while `mode = paper`. Live mode trips the kill switch (dormant).
4. **Backups (§14): no weekly full dump.** Nightly and weekly dumps exclude the five bulk tables (`raw_responses`, `orderbook_events`, `venue_trades`, `venue_quotes`, `odds_snapshots`); a sealed weekly partition of the two tape tables is archived once (pre-loaded decision 8). The encryption is the age v1 file format implemented with the `cryptography` package already in the dependency set (§4.3): neither the Mac nor the NAS has the `age` binary, and a new binary in the image is a dependency change this phase does not make. The files are decryptable by the standard `age` tool once the user installs it; until then the harness's own `backup-decrypt` is the reader.
5. **Message budget (§9.2)** is enforced in the writer as a token bucket of 60 order messages per minute per venue, plus the venue's own `read`/`write` buckets read from `GET /account/limits` (pre-loaded decision 5); a 429 is backoff-and-retry, never an outage signal.
6. **Pre-send invariant (§5.2)** gains the demo-host assertion: in `demo` env every signed request's host must end in `demo.kalshi.co` before signing (pre-loaded decision 1).
7. **Pricing budget (Amendment 4 to the pre-registration record, phase 3 addendum §0/§4 unchanged otherwise).** The variant loop scores the gate variant and the primary first on every tick and rotates only the secondaries; `price_budget_s` rises from 20 to 45 inside the unchanged `tick_budget_s = 100`. Measured cause: every daytime pricing run on 2026-09-08 (7 of 7; 83 of 272 since 2026-09-07) exhausted 20 s after one to four of seven variants over 4,541 gaps (about 6 s per variant), so the primary and the gate variant were scored on under half the ticks. Variant ids, configs, thresholds, families and cut-offs are untouched; the amendment dates the change and marks the runs before it.

## 1. Kalshi authenticated adapter (`harness/venues/kalshi/`)

### 1.1 Transport backstop (`http.py`)
`KalshiTransport(http: HttpClient, base_url, env, key_id, private_key_pem, clock_offset_ms, writes_enabled: bool, recorder)` routes every Kalshi call, REST and (in phase 5) RFQ, through one `request(method, path, params=None, json=None) -> FetchResult`.
- `method` not in {GET, HEAD} and `writes_enabled` false: raises `PaperModeViolation(method, path)` before any signing or network I/O. Tests: a GET passes; `POST /portfolio/events/orders` and `POST /communications/quotes` both raise with `writes_enabled = False`.
- Signs with the existing `sign_request` (RSA-PSS, `KALSHI-ACCESS-*` headers) using `now + clock_offset_ms` (from `clock.server_time_offset_ms`, refreshed hourly); the signed path is the URL path without query string.
- Writes one `venue_requests(venue, env, method, path, status, ts, elapsed_ms)` row per call through `recorder` (a callable; the executor and the CLI pass a session-backed writer, tests pass a list). Never headers, never bodies (pre-loaded decision 7).
- Retries: transport errors once; 429 sleeps `Retry-After` (default 2 s, cap 10 s) and retries up to three times, counting into `runs.notes` / the heartbeat as `venue_429`, never into the §9.4 outage counter; 5xx once. A non-idempotent POST is never resent blind: on a timeout after send the caller reconciles by `client_order_id` (§2.2).
- The public client (`KalshiPublic` over `HttpClient.get`) is unchanged: `HttpClient` has no `post`, `put` or `delete` method (test: `assert not hasattr(HttpClient, "post")`), so the recorder path cannot issue a non-GET by construction; its calls are not recorded in `venue_requests` (table 11 counts authenticated traffic; the recorder's reads are already in `raw_responses`).

### 1.2 Reader (`authed.py`: `KalshiReader`)
List and get methods only, all GET over the transport: `get_balance()`, `get_positions()`, `get_orders(status)`, `get_fills(since)`, `get_order(order_id)`, `get_account_limits()`, `get_exchange_status()`, `get_series(ticker)`. Decoders return dataclasses with Decimals (`OrderView`, `FillView`, `PositionView`, `Balance`, `Limits`); `outcome_side`/`book_side` are the direction source, legacy `side`/`action` are ignored when absent. Test: `assert not hasattr(KalshiReader, "place_limit")` and the same for `amend`, `cancel`, `cancel_group`.

### 1.3 Writer (`authed.py`: `KalshiWriter`, built only by `make_writer`)
`place_limit(intent: OrderIntent) -> VenueOrder`, `amend(order_id, prob, contracts, client_order_id, updated_client_order_id)`, `cancel(order_id)`, `cancel_group(group_id)`, `create_group(contracts_limit)`. Every order carries `post_only = true`, `order_group_id`, `cancel_order_on_pause = true`, `self_trade_prevention_type = maker`, `time_in_force = good_till_canceled`, `expiration_time` (int64 seconds), `exchange_index` from the venue market (pre-loaded decision 5), `client_order_id = intent uuid`. Amend fields are exactly `ticker, side, price, count, client_order_id, updated_client_order_id, exchange_index`; there is no expiry parameter (R8). The encoder maps `(side=yes, p)` to `bid @ p` and `(side=no, p)` to `ask @ 1 - p`, snapped to the market's `price_ranges` grid; the decoder inverts it; a round-trip property test covers both sides across the grid.
- Pre-send invariant (§5.2), independent of the encoder: `prob x contracts <= per_bet_cap_dollars`, `contracts <= contract_cap`, `0.01 <= p <= 0.99`, kill switch off, mode allows writes.
- Echo check: the response's `remaining_count + fill_count` equals the sent count and the decoded price equals the intent's, else `cancel` immediately and freeze the market 15 min (`venue_status` row `frozen`, reason `echo_mismatch`).
- Fee model: `GET /series/{ticker}` read at construction, cached; asserts maker 0.0175 and taker 0.07 on `KXNFL*` and `KXNCAAF*` (the phase 3 D14 comparison is reused).
- Limits: `get_account_limits()` at construction; tier and buckets logged into `runs.notes.venue_limits` and the Health block; the recorder's `kalshi_sleep_s` pause is derived from the read bucket (`max(kalshi_sleep_s, 1 / read.refill_rate)`), never lower than the setting.

### 1.4 Live guard (`make_writer`)
`make_writer(settings, env) -> KalshiWriter` is the only constructor (the class raises on direct construction outside the factory). `env = demo` returns a writer with `writes_enabled = True` only when both demo secret files exist and the resolved host ends in `demo.kalshi.co`. `env = prod` returns a writer with writes enabled only when all four hold: `LIVE_TRADING=1` in the environment, `Settings.mode == "live"`, a stored `gate_reports` row with `passed = true` for the gate variant, and `secrets/legal_decision` exists. None exists; tests assert `make_writer(settings, "prod")` raises `LiveGuardRefused` naming the first missing condition, for every subset of the four. `Settings.kalshi_env in {demo, prod}` (default `prod`), per-environment secret file settings (`kalshi_demo_key_id_file`, `kalshi_demo_private_key_file`), host settings pinned to the roadmap's strings (`kalshi_demo_base_url = https://external-api.demo.kalshi.co/trade-api/v2`, `kalshi_demo_ws_url = wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2`). Nothing in this phase constructs a prod writer outside tests.

### 1.5 Demo smoke (`harness kalshi-smoke --env demo`)
A runbook command and a verify.md check that runs only when `secrets/kalshi_demo_*` exist (`Path.exists()`, never contents). Sequence: assert host suffix; `get_balance()`; a zero balance journals "demo unfunded" and exits 0 (pre-loaded decision 1); `create_group(contracts_limit = 5)`; place one post-only YES bid at the market's lowest grid price for 1 contract on the nearest open `KXNFLGAME` market, far from the touch; echo check; `amend` price up one grid step and count to 2; `get_order`; `cancel`; `cancel_group`; place a second order with `expiration_time = now + 60 s`, wait, confirm expiry through `get_orders(status=resting)`; `get_fills`, `get_positions`. Prints a table and writes `venue_requests` rows tagged `env = demo`. Demo prices are not evidence and are never written to `orders`, `fills` or the tape.

## 2. Executor gateway and the dormant live path (`harness/execution/`)

### 2.1 Gateway interface
`OrderGateway` with `place(intent, market) -> PlacedOrder`, `cancel(order, reason)`, `amend(order, prob, contracts)`, `cancel_all(reason)`, `reconcile() -> ReconcileReport`. `PaperGateway` wraps today's `insert_order`/`insert_event` calls with no behaviour change (the phase 3 tests keep passing unchanged); `KalshiGateway(writer, reader)` implements the same interface over §1. `Executor.step()` picks the gateway from `Settings.mode`: `paper` (default, the NAS) uses `PaperGateway`; `live` requires `make_writer(settings, "prod")` to succeed, which it cannot (§1.4). The paper loop's timing, ordering, commits and skip labels are unchanged (a golden test replays a recorded day through both the old code path and `PaperGateway` and diffs the `order_events`).

### 2.2 Live-only behaviour (dormant, unit-tested against `FakeTransport`)
- Startup reconciliation before any loop: `get_orders(resting)`, `get_fills(since last known)`, `get_positions()`; any resting order unknown to `orders` or past its deadline is cancelled; positions are rebuilt; only then the loop starts (§9.1).
- Persisted intent uuid before send (already `orders.client_order_id`); after a timeout on send, `get_orders` filtered by `client_order_id` decides placed-or-not; never a blind resend (§9.1).
- Message budget: 60 order messages per minute per venue (token bucket); a breach trips the kill switch (§9.2). Three consecutive rejects on one order cancel it and freeze the market 15 min.
- Outage rule (§9.4): two consecutive auth (401/403) or geo errors mark `venue_status = unavailable` with the status code and a 120-character body excerpt in `reason`; nothing new is routed; manual re-enable (`harness venue-enable kalshi`, an operator command, journaled). 429 and 5xx never count.
- WS: a `seq` gap or 30 s without a ping stops repricing until the book is rebuilt from REST (the phase 3 dirty-book rule already gates fills; live adds "no reprice while dirty").

### 2.3 Sharding
`VenueMarket.exchange_index` already exists (phase 3) and is populated by `upsert_venue_markets`; the writer sends it on every order and amend; a dashboard data-quality line already counts non-zero shards. `DELETE .../orders/{id}` passes `exchange_index` too.

## 3. Risk gate (`harness/execution/risk.py`)

- **Equity.** Paper equity per exec variant = `bankroll + ledger cash delta + mtm_open` (the phase 3 `equity_snapshots` fields; `mtm_open` NULL counts as 0 with `mtm_coverage` shown). `equity_snapshots` gains additive columns `peak_equity_7d`, `drawdown_pct`, `drawdown_stop` (boolean). Rule: `drawdown_pct = (equity - peak_7d) / peak_7d`; `drawdown_stop` when `<= -0.20` (§9.3), evaluated at every equity sample (300 s).
- **Effect.** Paper: the dashboard Health block shows a red "drawdown stop" badge per stopped variant, and `signals` produced for that variant while stopped carry the label `drawdown_stop = false` in their filter labels (the candidate set excludes them, like any other label; the label is additive in the labels JSON and does not change the pre-registered decision rule for scoring: table 1 reports the stopped share). Live (dormant): `kill_active` is set with reason `drawdown_stop:<variant>`.
- **Tripwire.** `venue_requests` (§1.1); weekly report table 11 "Venue requests by method and env" asserts non-GET on `env = prod` = 0 and is additive (not a gate input, R1). A verify.md Layer 2b invariant counts `venue_requests where env = 'prod' and method not in ('GET','HEAD')` = 0.
- **Sanity checks** already in `plan.py` (`cap_labels`) stay; the gateway repeats the pre-send invariant independently (§1.3).

## 4. Backups (`deploy/backup/`, `harness/ops/backup.py`)

### 4.1 Dump sidecar (`app-backup`, image `postgres:16`, no build)
A Compose service on the same image as the database (it already ships `pg_dump 16.15` and `zstd`; the app image has neither and gains no packages). `command: ["/backup/loop.sh"]` with `deploy/backup/` bind-mounted read-only and `/volume1/docker/sports-harness/backups` bind-mounted read-write; `restart: unless-stopped`; connects over the compose network with the existing database URL from `.env` (no new secret). `loop.sh` sleeps to the next 03:30 America/Chicago (the container runs `TZ=UTC`; the script converts once per day with `date`), then runs `dump.sh nightly`; on Sundays at 03:30 it also runs `dump.sh weekly`. `dump.sh <kind>`: `pg_dump -Fc --exclude-table-data` for the five bulk tables (schema included, data excluded; parents and every partition by pattern) piped through `zstd -T2 -3` to `backups/<kind>/harness-<kind>-<UTC stamp>.dump.zst.tmp`, renamed on success, with a sidecar `.meta.json` (sha256, bytes, started/finished, pg_dump exit code, table list). Retention runs after each dump: keep 30 nightly and 8 weekly, deleting only files this script wrote (by name pattern) and never the encrypted files' plaintext before encryption is confirmed (§4.3). `ledger` and `gate_reports` are additionally exported as CSV (`COPY ... TO STDOUT`) into `backups/forever/` and never deleted.

### 4.2 Weekly partition archive
On Mondays at 04:00 CT, `dump.sh partition <table> <partition>` for each sealed weekly partition of `orderbook_events` and `venue_trades` from the previous ISO week that has no archive yet: `pg_dump -Fc -t <partition> | zstd -T2 -3` to `backups/partitions/`, once, then never touched (pre-loaded decision 8; between the archive and the RAID the tape has no other protection, said here and in the runbook). Retention: none (an archive is forever). Free-space guard: skip and journal when `/volume1` free is below 30 %.

### 4.3 Encryption and the key (`harness/ops/backup.py`, `harness/ops/agefmt.py`)
- `agefmt.py`: the age v1 file format for one X25519 recipient (header, `-> X25519` stanza, HKDF-SHA256 wrapping with ChaCha20-Poly1305, header HMAC, 64 KiB payload chunks with the last-chunk flag), encrypt and decrypt, streaming, using `cryptography` primitives only. `harness backup-keygen` writes `secrets/backup_age_key` (the private identity, `AGE-SECRET-KEY-1...` bech32) with mode 0600 and `deploy/backup_age.pub` (the recipient, `age1...`), on the Mac only; the Makefile never pushes the private key (its comment already says so) and pushes only the public key inside `deploy/`. The moment the loop generates the key it notifies the user with the copy-out instruction and adds the nag to Carried fixes until the user confirms (roadmap TODO).
- `harness backup-encrypt` (an `app-run` scheduler job every 10 min): for each plaintext `*.dump.zst` in `backups/` with a `.meta.json` and no `.age` sibling, encrypt streaming to `<name>.age.tmp`, rename, verify by decrypting the header and the first chunk against the public key's own derivation (structure only; the private key is not on the NAS), record a `backup_runs` row (kind, path, bytes, sha256 of the plaintext, sha256 of the ciphertext, status, timings), then delete the plaintext. If the public key file is absent the job records `skipped: no recipient` and leaves plaintexts in place (a feature switched on `Path.exists()`).
- `harness backup-decrypt <file.age> --out <path>` runs on the Mac with `secrets/backup_age_key`.

### 4.4 Restore drill (a backup is not done until one has run)
Two halves, both recorded in `backup_runs` with `kind = drill`:
1. NAS half (the sidecar, run by the controller over ssh: `docker compose run --rm app-backup /backup/drill.sh <nightly file>`): `createdb harness_drill`, `pg_restore` the plaintext (decompressed from the `.age` file the Mac half decrypted and copied back, or from the plaintext when the drill runs before encryption in the same night), count rows for every non-bulk table in both databases, print the comparison, `dropdb harness_drill` (the scratch database is created and dropped by the drill only; nothing touches `harness`).
2. Mac half (`harness backup-decrypt` on one nightly `.age` file copied with scp): the decrypted sha256 must equal `backup_runs.plaintext_sha256`.
The verify.md Layer 2 row (Task last): newest `backup_runs` nightly `ok` younger than 26 h with `bytes > 0`; a `drill` row with `rows_match = true` within the phase; `ls backups/` shows `.age` files and no plaintext older than 30 min.

## 5. Alembic baseline and dependency pins (`migrations/`, `harness/db/migrate.py`)

- Baseline `0001_baseline` hand-written from `create_schema` (tables, the BRIN and functional unique indexes, the partitioned parents with their current partitions attached by name, views); `alembic stamp head` on the NAS at deploy for the existing database (the baseline is not executed against it), `alembic upgrade head` on an empty database creates the same schema. Verification: a test builds one database with `create_schema` and one with `alembic upgrade head` and compares the SQLAlchemy `inspect()` catalogue (tables, columns with types and nullability, primary keys, unique constraints, indexes with their expressions, partitioning read from `pg_partitioned_table`) to be equal, without `pg_dump` (the Mac has none).
- `env.py`: `include_object` excludes the partitioned tables and their partitions, every BRIN and functional index, and reflected-only objects; the migration connection runs `SET lock_timeout = '5s'` and `SET statement_timeout = '300s'`; a helper `concurrent_index(name, table, cols)` uses `op.get_context().autocommit_block()` and is the only way to create an index on a bulk table (a test greps the migrations for `create_index` on a bulk table outside it).
- Deploy order: `make deploy-nas` runs `backup-precheck` (the newest nightly `backup_runs` row is `ok` and younger than 26 h, else it runs `dump.sh nightly` first) then `alembic upgrade head` before `init-db`; `init-db` keeps `create_schema` for tests and empty databases; a numbered rollback in `docs/runbooks/alembic.md`. DROP, `ALTER COLUMN ... TYPE` and non-concurrent bulk indexes are gates (never written by the loop).
- Pins: `constraints.txt` gains exact pins for `alembic` and `Mako` appended below the existing lines (§11 D7); nothing else in the file changes; `pip install -c constraints.txt .` stays.

## 11. Decisions taken on the user's behalf

- **D1 age format in Python, not the `age` binary (§0.4, §4.3).** Source: model. Rationale: no `age` on the Mac or NAS; adding a binary to the image or a pip package needs a dependency change beyond the one in D7. Cost if wrong: a format bug makes files undecryptable by the standard tool, caught by the round-trip and known-answer tests and by the Mac half of the drill (self-consistency); age-CLI compatibility is confirmed the day the user installs `age` and runs `age -d` once (a Needs-you line, optional). Blast radius: file. Reversal: `brew install age` on the Mac and swap the encryptor for a subprocess in one module.
- **D2 dump sidecar on the postgres image (§4.1).** Source: model. Rationale: `pg_dump 16` and `zstd` exist there and nowhere else; no packages added anywhere. Cost if wrong: one more container (about 20 MB RSS idle). Blast radius: NAS container. Reversal: remove the service.
- **D3 `signals` stays in the nightly dump (§8).** Source: pre-loaded decision 8 names exactly five excluded tables. Cost if wrong: 100-150 GB of nightlies by week 3. Reversal: a dated amendment adding `signals` to the excluded list.
- **D4 Gateway interface with `PaperGateway` (§2.1).** Source: model. Rationale: the only way to build the live path without touching paper behaviour; the golden replay test proves paper is unchanged. Cost if wrong: an indirection layer. Blast radius: file. Reversal: inline the paper calls.
