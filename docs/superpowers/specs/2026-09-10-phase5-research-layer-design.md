## 0. Amendments to v2 and to the roadmap text

- **0.1 (§7.1) The veto is asynchronous and post-hoc.** A signal is not held for the model. The executor's decision stands; the veto worker reads the signal afterwards, calls both models, and records the decision on the signal for H9. Reason: an Opus call with web search takes 10-30 s and the executor's loop ceiling is 7.5 s. "Promotion to enforcing" (§7.1) stays a user gate and is out of scope.
- **0.2 (§7.1) Subject and cache.** The cache key is `(game_id, market_type)` for 30 minutes, invalidated by a change in the game's ESPN status or a new weather snapshot for the game; the roadmap's `subject_id = signal_id` names the triggering signal; other signals inside the window link to the same call through `veto_decisions`.
- **0.3 (R:220, U4) The caps cover the pair.** `veto_daily_usd_cap` $25 and `veto_weekly_usd_cap` $150 are totals across both models and the annotator; a call's cost includes web searches billed per search. Enforcement is pre-call by projection and post-call by the usage fields (D9, D10).
- **0.4 (R:217) "default effort" is written as `high`** (the API's default), pinned in the prompt hash.
- **0.5 (§8.1) Props are not fetched at build time in phase 5.** Smart-card legs come from moneyline, spread and total at DraftKings prices already in `odds_snapshots`. Reason: no extra Odds credits and no new endpoint this phase; the spec's "props only if fetched via the event-odds endpoint" stays available to a later phase.
- **0.6 (§8.1) "Recorded in `parlays`" is superseded** by the dashboard spec §3.9 tables, which exist.
- **0.7 (R:235, F64) The RFQ listener's key.** It runs on the read-scoped pair `secrets/kalshi_read_key_id` + `secrets/kalshi_read_private_key.pem` when both exist (`Path.exists()`), else on the existing production key. Reason: the listener holds a key only for the WebSocket handshake; it subscribes to one channel and its module contains no write path; the transport refuses `POST /communications/quotes` before signing (`PaperModeViolation`, `harness/venues/kalshi/http.py:176`). The read-scoped key narrows the blast radius when the user provides it; its absence does not idle the feature (D6).
- **0.8 (R:241, F71) "non-200 from the subscribe"** is read as: an HTTP status other than 101 on the handshake, an error frame with code 8, 9, 10, 11 or 27 in reply to the subscribe, or a permission error at any point. Each idles the listener and writes `venue_status` (D8).
- **0.9 (R:207) Futures discovery.** `GET /series` has no ticker-prefix filter; discovery is a client-side filter of the football categories' series over the prefixes `KXNFL` and `KXNCAAF`, then `GET /markets?series_ticker=…&status=open` per series with `mve_filter=exclude` (D1 in §1).
- **0.10 (R:209) NWS hourly schema is unverified** by documentation; the first weather task records one live `forecastHourly` response through `store_raw` and pins the parser to the recorded field names before any parsing code is merged (D3).
- **0.11 (§8.2) Decline rules.** A cross-game RFQ is one whose `mve_selected_legs` carry distinct `event_ticker`s; any RFQ with two legs from one event is declined and recorded with `declined_reason = same_event`; an RFQ whose legs lack a `direct` sharp fair value or whose disagreement exceeds the threshold is declined with `no_fair` / `disagreement`. No quote is ever sent; "quote" means a stored row.

## 1. Components

### 1.1 Futures and ladder weekly snapshots (item a, H7)

- **Job** `futures_snapshot`, APScheduler `CronTrigger` Tuesdays 09:00 America/Chicago in `harness/scheduler.py` (the first cron trigger in the harness; the pinned APScheduler 3.11.3 ships it), plus `harness futures snapshot` for a hand run. Each pass writes a `job_runs` row (`job = 'futures'`) so the Tuesday 09:30 duty reads it.
- **Discovery**: `GET /series?category=<football categories>` (the categories come from `GET /search/tags_by_categories`, recorded once per pass), filtered client-side to tickers starting `KXNFL` or `KXNCAAF` whose `frequency` is not a per-game one; then `GET /markets?series_ticker=<t>&status=open&limit=1000&mve_filter=exclude` with cursor paging. Per-game series already recorded by the recorder (`KXNFLGAME`, `KXNFLSPREAD`, `KXNFLTOTAL`, `KXNCAAFGAME/S/T`) are excluded by prefix list.
- **Storage**: raw bodies through `store_raw(source='kalshi_futures')`; normalized rows in `futures_snapshots(id, run_id, snapshot_week (ISO), series_ticker, event_ticker, market_ticker, market_type, strike_type, floor_strike, cap_strike, yes_bid, yes_ask, last_price, volume_fp, open_interest_fp, close_time, fetched_at)` with an index on `(series_ticker, snapshot_week)`. Prices are the `*_dollars` fixed-point strings decoded as Decimal (the phase 4 decoder).
- **Budget**: at most 200 requests per pass, 0.1 s between pages; the pass stops and records `budget_exhausted` in `job_runs.notes` beyond that. No Odds credits.
- **H7 measurement** is a later report table (week-over-week drift of ladder mids toward 0.50); this phase records only.

### 1.2 NWS forecast snapshots (item b, H6)

- **Stadiums**: a committed `harness/weather/stadiums.yaml` keyed by `(sport, team_abbreviation)` with `name, lat, lon, roof ∈ {open, dome, retractable}, source` (a public-source URL per row), written by the implementer from public sources for the 32 NFL and the FBS teams present in `teams`; a `neutral_sites.yaml` override keyed by `(sport, home_team_abbreviation, away_team_abbreviation, kickoff_date)` for known neutral games. Coverage test: every `teams` row with `popularity_tier` set has a stadium row or is listed in `stadiums_missing.txt` with a reason. A game whose home team has no row is skipped with the reason recorded once per game in `job_runs.notes`; a dome is skipped; a retractable roof is fetched and labelled `roof = retractable`.
- **Client**: `harness/feeds/nws.py`, its own read-only httpx client (precedent `harness/venues/kalshi/http.py:16-30`) with the fixed `User-Agent: sports-harness/1 (self-hosted research harness)` and `Accept: application/geo+json`; GET only; host `api.weather.gov` (invariant 8). The shared `HttpClient.get` is unchanged (ESPN keeps httpx's default agent).
- **Flow**: `/points/{lat},{lon}` once per stadium, cached forever in `weather_points(sport, team_abbreviation, office, grid_x, grid_y, forecast_hourly_url, fetched_at)`; then `forecastHourly` per outdoor game with kickoff inside 72 h, once per hour, inside the recorder tick as its own source (`cadence`: every 60 minutes when `interval_for` allows a tick; a 20 s budget inside `tick_budget_s`; five-second retry once on 429; any other non-200 recorded and skipped). Raw through `store_raw(source='nws')`; normalized `weather_snapshots(id, run_id, game_id, fetched_at, period_start, temperature_f, wind_mph, wind_dir, precip_pct, short_forecast, roof)` for the periods covering kickoff −1 h to +4 h, indexed `(game_id, fetched_at)`.
- **Schema pin (0.10)**: task one records a live response and commits the recorded field list beside the parser; the parser rejects a body that lacks a pinned field with a `job_runs.notes` entry, never a guess.

### 1.3 Parlay CLI (item c)

- **Command** `harness parlay build --sport cfb|nfl [--week W]` writes a `parlay_cards` row (`status = proposed`) with `parlay_legs`; `harness parlay placed <card_id> --payout <dk_american_odds> --stake <usd>` writes `parlay_placements` and the `parlay_ledger` stake row; `harness parlay show`. Config `harness/parlay/parlay.yaml`: weekly budget 50, smart 25, lottery 5, lottery cards max 3, anchor teams `LSU`, `NO`, leg pool thresholds.
- **Legs**: smart card 3-4 legs from different games, anchor an LSU or Saints moneyline, spread or total; other legs from the +EV pool (signals with `direct` fair and edge over the threshold in the last 6 h) priced at the newest `odds_snapshots` row for `(game_id, market_type, outcome, book='draftkings')` no older than 30 minutes; a leg without such a row is not eligible; an anchor without one ends the build with exit code 2 and the message `no anchor priced`. Lottery card 6-8 legs, correlated legs allowed and labelled per §8.1; `estimated_payout = Π decimal odds`, `true_probability = Π sharp p` (independence assumed, stated on the card), implied hold from the DK payout on `placed`.
- **Budget**: a hard weekly cap: `placed` refuses when this ISO week's `parlay_ledger` stakes plus the new stake exceed $50; a proposed card older than 7 days becomes `expired`. The unallocated $10 is unspent by design.
- **Rationale**: from a template (fan voice, cites the leg numbers) unless `secrets/anthropic_api_key` exists, then one `claude-opus-5` call (effort `low`, no tools, 200 output tokens, counted against the U4 caps as `kind = 'parlay'`); the template is the fallback on any error. Text handling F60: the rationale is sanitized (`sanitize_reason`) and capped at 300 characters before storage; the Ticket surface already renders it as text.
- **Settlement**: `parlay_grade` stage registered after `settle` in the settlement chain (hourly with it): for each `placed` card, each leg resolves through `resolve_market`'s push rules once its game is final; the card grades `won/lost/void` when every leg is graded; `parlay_ledger` gets the `return` row. **Leg probabilities**: the recorder tick writes `parlay_leg_probs(leg_id, ts, sharp_p)` from the leg's `direct` fair value while a card is `placed` and its game's kickoff is inside 24 h (one row per leg per tick).

### 1.4 Shadow veto (item d, H9)

- **Worker**: `harness research-worker`, a new compose service `app-research` (same image, no ports, restart unless-stopped), dormant without `secrets/anthropic_api_key` (it starts, logs `research: dormant, no key`, sleeps). It polls `veto_queue` every 5 s and runs at most two calls concurrently.
- **Queue**: the executor enqueues `(signal_id, game_id, market_type, enqueued_at)` for every signal that produced an intent (placed or held), at most one row per `(game_id, market_type)` per 30 minutes (0.2). The queue is a table with a unique index on `(game_id, market_type, window_start)`.
- **Features (precomputed by the harness, D1 of the roadmap)**: fair history across books over 6 h (from `fair_values` and `odds_snapshots` mids at 5-minute buckets), venue price history over 6 h (`venue_quotes` mids), disagreement (max minus min fair across books), fair staleness, time to kickoff, the newest weather snapshot for the game, the ESPN status; injuries are `not available` (no injury feed exists). Every timestamp is explicit UTC and America/Chicago.
- **Prompt**: one frozen system prompt (cached, `cache_control ephemeral`, the last breakpoint before the features), versioned by hash in `research_notes.prompt_hash`; the model defaults to `proceed`; `reduce` or `veto` require quoted evidence ids from the retrieved snippets; retrieved pages are quoted, untrusted data under a fixed instruction. Tools: `web_search` with `max_uses = 3`, `allowed_domains` unset, the result blocks stored as snippets (URL, timestamp, snippet id, text capped at 2,000 characters). Output: `output_config.format` json_schema `{decision ∈ {proceed, reduce, veto}, confidence 0-1, reason ≤ 300 chars, evidence_ids []}`, `additionalProperties false`. Primary `claude-opus-5`, effort `high`, adaptive thinking (the default); shadow `claude-sonnet-5`, same prompt, same effort, every call, recorded, never used.
- **Cost and caps (0.3)**: `research_spend(day (America/Chicago), kind, model, calls, input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, searches, usd)`; cost per call = tokens at list price (cache reads ×0.1, cache writes ×1.25) plus searches × $0.01; searches counted from `server_tool_use` blocks in the response content (the SDK's usage sub-field is used when the installed version exposes it). Pre-call: the worker refuses a call when today's total plus the worst case of the pair (8,000 input tokens, 1,500 output tokens, three searches for each model) would exceed $25, or this week's plus the same exceeds $150; the skipped signal gets `veto_decisions.decision = 'veto_skipped_budget'`. Post-call: the actual cost is added. A call in flight when the cap is crossed completes and is recorded. Dormant means "until the next America/Chicago day (or Monday for the weekly cap)". Pulse shows the day's spend and the dormant state (a `research_budget` WATCH rule); the 09:00 daily line reads the same row.
- **Records**: `research_notes(call_id uuid, kind ∈ {veto, annotate, parlay, study}, subject_id, model, effort, prompt_hash, features JSONB, snippets JSONB, tool_calls JSONB, output JSONB, usage JSONB, cost_usd, latency_ms, request_id, created_at, replay bool default false, arm text null)`: two rows per veto call (primary and shadow) under one `call_id`. `veto_decisions(signal_id, call_id, decision, confidence, from_cache bool, created_at)`: one row per signal; H9 joins `veto_decisions` to the signal's later CLV and markouts, within the primary only, by decision label (R2: no `no_veto` variant).
- **Alert**: a veto rate over 25 % of decided signals in 24 h lights a Pulse WATCH rule `veto_rate` (threshold home in `harness/health.py`).
- **Injection case**: the design review's injection test passes a snippet containing an instruction to change the decision; the test asserts the output is `proceed` with no evidence id pointing at it, and that the reason contains no markup or control characters (F60).

### 1.5 Weekly report annotator (item e)

- After `report_weekly` on Mondays (the same cron family as 1.1: Monday 09:15 CT, after the report run's own schedule), one `claude-opus-5` call (effort `high`, no tools, structured output `{bullets: [≤5 × ≤ 240 chars]}`) receives the ten tables as text and must cite cells as `t<k>[row,col]`; a bullet whose citations do not resolve to real cells is dropped; the survivors are stored in `report_annotations(report_run_id, model, prompt_hash, bullets JSONB, cost_usd, created_at)` and rendered by the report inside a fenced block titled "model-written, unverified". Dormant without the key; counted against the caps as `kind = 'annotate'`.

### 1.6 Combo RFQ listener (item f, H5)

- **Socket**: the existing `WsRecorder` connection (settings host `wss://api.elections.kalshi.com/trade-api/ws/v2`, invariant 8) sends a second subscribe frame `{"id": 2, "cmd": "subscribe", "params": {"channels": ["communications"]}}` after the market channels' ack; the channel ignores market specification. Frames of type `rfq_created` / `rfq_deleted` are routed to `harness/rfq/listener.py`; quote-event types never arrive (the harness never creates a quote) and are logged and dropped if they do.
- **Storage on arrival**: `rfqs(id text pk, received_at, created_ts, event_ticker, market_ticker, contracts_fp, target_cost_dollars, mve_collection_ticker, legs JSONB (from mve_selected_legs), raw JSONB (the frame's msg, ≤ 8 KB), status ∈ {open, deleted}, deleted_ts)`; free text inside `raw` is never rendered raw and never placed in a prompt (F60): the report's RFQ cell shows a 120-character quoted excerpt of `market_ticker` only.
- **Quote computation (stored, never sent)**: for a cross-game RFQ whose legs all have a `direct` sharp fair value with disagreement under the threshold: `fair = Π leg fair`; `yes_bid = fair − margin × legs`, `no_bid = 1 − fair − margin × legs`, margin default 0.03 per leg (setting); collateral cap per RFQ (setting, default $50 notional); F72: `fee_branch = nfl_only_independent` when every leg's `event_ticker` starts `KXNFL` and they are distinct, else `other` with the maker fee subtracted; both branches' bids stored. Rows in `rfq_quotes(id, rfq_id, computed_at, legs int, fair, margin_per_leg, yes_bid, no_bid, fee_branch, fee_subtracted, yes_bid_other_branch, no_bid_other_branch, declined_reason, graded_at, closing_fair, pnl_yes, pnl_no)`.
- **Grading**: the settlement stage `rfq_grade` (after `settle`) grades each quote at the legs' settlement against the product of closing leg fair values, both branches; H5's table 10 reads `rfq_quotes`.
- **Idling (0.8)**: on a handshake status other than 101, a subscribe error frame (codes 8-11, 27), or any permission error, the listener sets `venue_status(venue='kalshi_rfq', env='prod', status='unavailable', reason=<120 chars of the venue's text>)` and stops resubscribing for one hour; the market channels are unaffected. A silent socket is the recorder's existing staleness path.
- **Refusal tests**: the module's source contains no `POST`, no `quotes` path and no reference to the write client (a static test); the transport test asserts `POST /communications/quotes` raises `PaperModeViolation` before any I/O; a frame test feeds a hostile `raw` and asserts nothing of it reaches a rendered string.

## 8. Decisions taken on the user's behalf

Each: source (pre-loaded | model), rationale, cost if wrong, blast radius, reversal.

- **D1 futures discovery by category then prefix filter** (model): the API has no prefix filter; cost: a series outside the football categories is missed; radius: file; reversal: widen the category list.
- **D2 stadium YAML plus neutral-site overrides, dome skipped, retractable fetched and labelled, missing skipped** (model): the only data source is public; cost: a wrong coordinate yields a wrong forecast for one team; radius: file; reversal: edit the row.
- **D3 NWS schema pinned from one recorded response** (model): documentation did not verify the hourly body; cost: one extra task step; radius: file; reversal: none needed.
- **D4 NWS client separate from the shared HttpClient** (model): ESPN rejects custom agents; cost: one more small client; radius: file; reversal: merge later.
- **D5 NWS fetch inside the recorder tick, hourly, 20 s budget** (model): no new process; cost: a slow NWS hour delays the tick by up to 20 s (inside `tick_budget_s`); radius: file; reversal: move to a job.
- **D6 RFQ listener runs on the production key until a read-scoped pair exists** (model, 0.7): the listener cannot write; cost: the production key is held by one more code path (read-only by construction); radius: file; reversal: set `rfq_listener_enabled = false` or provide the read-scoped pair.
- **D7 RFQ frames on the existing socket** (model): the channel ignores market specification; cost: a communications error frame shares the socket's reconnect path; radius: file; reversal: a second socket.
- **D8 F71 mapping to `venue_status('kalshi_rfq')`** (model, 0.8): cost: none; radius: DB additive; reversal: none.
- **D9 caps enforced pre-call by projection and post-call by usage, searches counted from response blocks** (model, 0.3): the SDK's usage may not expose search counts; cost: a projection that is too conservative skips a call near the cap; radius: file; reversal: tune the worst-case constants.
- **D10 the caps cover the pair plus the annotator and parlay calls** (model): the user's cap is a spend cap; cost: fewer veto calls per day than a per-model reading would allow; radius: file; reversal: split the caps (a settings change).
- **D11 effort `high` explicit; tool type pinned at implementation** (model): cost: none.
- **D12 research_notes discriminator `kind` and `replay`/`arm`** (model): cost: none; reversal: a column.
- **D13 raw RFQ message in `rfqs.raw` JSONB, not `raw_responses`** (model): builders may not read `raw_responses`, and the report needs the legs; cost: 8 KB per RFQ; radius: DB additive; reversal: move to `raw_responses`.
- **D14 DraftKings leg price newest row ≤ 30 min, no props, anchor missing ends the build** (model, 0.5): cost: a card cannot be built when DK is stale; radius: file; reversal: widen the age.
- **D15 hard weekly $50 cap at `placed`, proposed cards expire after 7 days, $10 unallocated** (model): cost: none; reversal: yaml.
- **D16 `parlay_grade` after `settle`, leg probs from the recorder tick inside 24 h** (model): cost: one hourly stage; reversal: cadence.
- **D17 veto asynchronous and post-hoc in `app-research`** (model, 0.1): cost: one container; the decision never affects execution (that is the design); radius: NAS container; reversal: remove the service.
- **D18 H8 reported "not collected" this phase** (pre-loaded R:255, model for the timing): the Novig feed accrues; cost: H8 unmeasured until a later phase; reversal: a report table over stored data at any time.
- **D19 veto-rate WATCH at 25 % of decided signals in 24 h** (model): cost: a noisy rule; reversal: threshold in `harness/health.py`.
- **D20 queue admission: one call per `(game_id, market_type)` per 30 minutes** (model, 0.2): cost: a signal inside the window inherits a decision made up to 30 minutes earlier (recorded as `from_cache`); reversal: the setting.
